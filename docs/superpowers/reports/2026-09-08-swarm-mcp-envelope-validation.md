# Bounded MCP envelopes and JSON validation

The shared protocol crate now validates complete JSON and MCP request envelopes without constructing a payload tree. It preserves exact request IDs and borrowed parameter text, rejects duplicate decoded keys at every depth, and leaves dispatch and native authority to the later host adapter.

The JSON scanner uses fixed iterative storage: 64 container frames, 256 live ancestor keys, at most 64 keys per object and 128 decoded bytes per key. Input is bounded to 16 MiB and work to 524,288 nodes. Its conservative scratch accounting is 34,242 bytes with no heap scratch. A generated 7,482,286-byte core-shaped page used 90,113 nodes. MCP separately limits input to 4 MiB after the line delimiter is removed; literal CR/LF, batches, explicit null IDs, unknown envelope fields, non-object params, malformed Unicode and trailing data are rejected. IDs above 2^53 remain exact.
