# Chat View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pane running Claude Code flips into a live chat rendering of the session — bubbles, density-controlled tool chips, chat input forwarded to the PTY, and interactive TUI prompts surfaced as answerable cards inside the chat.

**Architecture:** Rust tails the session's JSONL via byte offsets and normalizes entries to a `ChatEntry` model (tauri commands `chat_feed_open`/`chat_feed_poll`); the UI polls while mounted and renders `ChatView` over the still-running terminal in the same pane. A pure `PromptDetector` classifies the live xterm buffer into prompt cards whose buttons synthesize keystrokes.

**Tech Stack:** Rust (serde, existing `llm_sessions`/`transcript` modules), TypeScript (React 19), `react-markdown` + `rehype-sanitize` (new npm deps), vitest, theme tokens.

**Spec:** `docs/superpowers/specs/2026-08-10-chat-view-design.md` — read first; authoritative on every behavior.

## Global Constraints

- Poll cadence 500 ms, only while a chat view is mounted. Initial window: last 256 KiB. Prompt-retry delay ~800 ms, one retry. Input history cap 50. Fallback card shows last ~12 non-empty terminal lines.
- The chat NEVER writes the transcript file, never auto-answers a prompt, never blocks the PTY.
- Live panes' terminal stays mounted and attached under the chat (it feeds the detector).
- Density values `"chips" | "smart" | "full"`; smart auto-opens tools with status "error", edit diffs, and test-run details.
- Defaults via one local module (`ui/src/chat/chatDefaults.ts`: view `"terminal"`, density `"smart"`) — the settings fields land in a PARALLEL lane; do NOT edit `ui/src/settings/**`. A marked `// SETTINGS-INTEGRATION` comment sits where the defaults are read; the merge wires it.
- Markdown: `react-markdown` + `rehype-sanitize` default schema, raw HTML stripped, no other new rendering deps, nothing loaded from the network.
- `exactOptionalPropertyTypes` ON: `{...(x ? { x } : {})}`. No hardcoded absolute machine paths. Match surrounding idiom.
- Cargo from Git Bash after `export PATH="$HOME/tools/mingw64/bin:$HOME/.cargo/bin:$PATH"`; termx-ui tests run FROM `ui/src-tauri` (own workspace). UI: `npm ci` first in the worktree.
- Gates: ui `npx tsc -b` clean; `npx vitest run --reporter=dot` ≥ 914 + new; e2e ≥ 6 (build host binary once); `cargo test -q -p termx-ui` ≥ 162 + new; `cargo test -q -p termx-host` stays 154 (host untouched).
- Never `git stash`; never junction/symlink into the main repo; one commit per task.

**Interfaces — Produces (serde snake_case → the TS types in Task 3 mirror this exactly):**

```rust
#[derive(Serialize, Clone)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum ChatEntry {
  User      { id: String, ts: i64, text: String },
  Assistant { id: String, ts: i64, markdown: String },
  Thinking  { id: String, ts: i64, text: String },
  Tool      { id: String, ts: i64, name: String, title: String, summary: String,
              status: ToolStatus, detail: String },       // status: running|ok|error
  System    { id: String, ts: i64, text: String },
}
pub fn normalize_claude_lines(lines: &[&str]) -> Vec<ChatEntry>;
```

Adapter rules (from the spec + existing parser knowledge): user text also arrives inside `queue-operation` events — read both; `tool_use` opens a Tool entry with status running; the matching `tool_result` (by tool_use id) fills `detail` + final status (error flag → `error`); un-matched results or unknown entry types → skipped, counted, and surfaced as one trailing `System` entry ("N entries unreadable") per batch; thinking blocks → `Thinking`; compaction/summary boundaries → `System`. `title`/`summary` composed per tool name (Edit → file + "+A −B" from the diff payload when present; Bash → the command's first line; Read/Grep/Glob → target; unknown tools → name + first arg). Malformed JSON lines skip-and-count — never panic.

### Task 2: Rust — feed commands (open/poll, truncation, partial lines)

**Files:**
- Modify: `ui/src-tauri/src/chat_feed.rs`, `lib.rs` (register commands)
- Test: same module, temp-file tests

**Interfaces — Produces (tauri commands):**

```rust
#[tauri::command] fn chat_feed_open(path: String) -> Result<FeedWindow, String>;
#[tauri::command] fn chat_feed_poll(feed_id: u64) -> Result<FeedWindow, String>;
#[tauri::command] fn chat_feed_close(feed_id: u64);
// FeedWindow { feed_id: u64, entries: Vec<ChatEntry>, offset: u64, reset: bool }
```

`open`: read the last 256 KiB via `read_window_at`, drop the first partial line, normalize, return with the end offset. `poll`: read appended bytes since `offset`; parse complete lines only, carry a partial trailing line in feed state; if file size < stored offset (truncated/rewritten) → re-open the tail window and return `reset: true`. Feed state in a mutex map keyed by `feed_id`; `close` drops it. Path validation: must be an existing file under the session roots (`llm_sessions::default_roots`) — reject anything else (the command surface must not become an arbitrary-file reader).

  onUpdate(l: () => void): () => void;

### Task 5: UI — PromptDetector (pure) + keystroke computation

**Files:**
- Create: `promptDetector.ts`, `__tests__/promptDetector.test.ts`, text fixtures in `__tests__/fixtures/prompts/*.txt`

**Interfaces — Produces:**

```ts
export type DetectedPrompt =
  | { kind: "menu"; question: string; options: { label: string; index: number }[];
      selectedIndex: number; raw: string[] }
  | { kind: "confirm"; question: string; raw: string[] }
  | { kind: "unknown"; raw: string[] };
export function detectPrompt(visibleLines: string[]): DetectedPrompt | null;  // null = ordinary output
export function keysForMenuAnswer(prompt: { selectedIndex: number }, targetIndex: number): string;
  // (target-selected) arrow keys ("\x1b[B"/"\x1b[A") then "\r"
```

v1 patterns, each with a captured-screen fixture: Claude Code permission dialog ("Do you want to …" + `❯`-selected option list, with or without numbers), AskUserQuestion option menu, plan-approval prompt ("Would you like to proceed?"), folder-trust prompt. `unknown` fires only when the tail of the screen looks interactive (last non-empty line ends with a selector/`?`/`:` pattern AND output has stalled — the stall signal is supplied by the caller, not detected here). Negatives (scrolling build logs, plain prompt lines) must return null. Capture fixtures by running Claude Code locally if available; otherwise transcribe layouts exactly from Claude Code's public UI and mark each fixture with its provenance.

### Task 6: UI — PromptCard + detection wiring

**Files:**
- Create: `PromptCard.tsx`; modify `ChatView.tsx` (card slot above the input)
- Test: `__tests__/PromptCard.test.tsx`

Wiring: ChatView receives `terminalSnapshot: () => string[]` (visible xterm lines — provided in Task 8) and a `transcriptIdle: boolean` (no feed entries for >2 s). On terminal-output change (debounced ~300 ms) while idle, run `detectPrompt`; `menu`/`confirm` → card with question + option buttons; button click → `sendKeys(keysForMenuAnswer(...))` (confirm → the shown affirmative/negative key), card enters "answering"; after ~800 ms re-detect: gone → answered state (card collapses to a one-line system chip); unchanged → one retry, then degrade to `unknown` form. `unknown` → card with last ~12 non-empty lines (mono, read-only), free-text box (Enter → `sendKeys(text + "\r")`), and Open-terminal button. Cards never auto-send anything.
