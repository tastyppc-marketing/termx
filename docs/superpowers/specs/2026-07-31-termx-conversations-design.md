# TermX Conversations — LLM Session Manager (Design)

Date: 2026-07-31. Status: approved in conversation (Michael), pending spec review.
Builds on: 2026-07-30 cwd/settings batch (scope paths, OSC 9;9 prompt hooks,
settings pane, app-file storage, folder searcher).

## Goal

A session manager inside TermX for LLM CLI conversations: discover every
Claude Code and Codex session on the machine, show where each one happened and
what it was about, organize them into UI-native folders, and resume any of them
with one click — TermX opens a tab in the session's directory and types the
resume command. Removes the "cd around and hunt for /resume" workflow.

## Non-goals (v1)

- No whole-drive scanning. Session stores are centralized; each session records
  its own cwd. Discovery reads known roots only.
- No Grok/Gemini adapters (architecture admits them later).
- Folders never move anything on disk; they are TermX metadata only.
- No editing/deleting of provider session files. Read-only discovery.
- No live "session is currently open in another terminal" detection.

## 1. Provider adapters (Rust, Tauri layer)

New module `ui/src-tauri/src/llm_sessions/` — one adapter per provider behind a
common record type:

```rust
pub struct SessionRecord {
    pub provider: String,      // "claude" | "codex"
    pub id: String,            // provider-native session id
    pub title: String,         // best available human title (never empty; falls back to id)
    pub cwd: Option<String>,   // absolute dir the session ran in
    pub file_path: String,     // absolute path of the source file (index key)
    pub updated_at_ms: u64,    // last activity (file mtime or index timestamp)
    pub summary: Option<String>,   // short one-liner harvested from disk
    pub recap: Option<String>,     // multi-line recap harvested from disk (see §6)
}
```

**Claude adapter.** Root: `%USERPROFILE%\.claude\projects\<slug>\*.jsonl`
(top-level session files only; skip subdirectories such as `tool-results`).
Session files can exceed 100 MB, so the adapter reads only the first 256 KB and
last 256 KB of each file and harvests, line-tolerantly (a malformed or
truncated line is skipped, never an error):

- `cwd`: first `"cwd":"..."` value seen. Fallback: decode the dir slug
  (`C--Dev-TermX` → `C:\Dev\TermX`) — fallback only, because dashes in real
  directory names make slug decoding ambiguous.
- `summary`: the LAST `{"type":"summary","summary":...}` line seen (harness
  keeps these current).
- `recap`: the NEWEST compaction block — the user-role message whose text
  starts with "This session is being continued" — trimmed to 2,000 chars.
  Absent in most sessions; that is fine (see §6).
- `title`: first user message text (first 120 chars, control chars stripped);
  fallback `summary`; fallback the session id.
- `updated_at_ms`: file mtime. `id`: file stem (uuid).

**Codex adapter.** `%USERPROFILE%\.codex\session_index.jsonl` supplies
`{id, thread_name, updated_at}` → title + recency. `cwd` comes from the head
of the matching rollout file under `%USERPROFILE%\.codex\sessions\` (bounded
head read; if not found, `cwd: None`). `summary`/`recap`: None (thread_name
already serves as the short label; the LLM engine can fill gaps per §6).

## 2. Incremental index

Cold-harvesting ~1,000 project dirs on every open is too slow, so scan results
persist to a new app file **`sessions_index_v1.json`** (added to the storage
allowlist beside `settings_v1.json` / `ui_state_v1.json`):

```json
{ "version": 1,
  "entries": { "<file_path>": { "mtimeMs": 0, "size": 0, "record": { } } } }
```

Tauri command `list_llm_sessions(force: bool) -> Vec<SessionRecord>`:
stat-compare every candidate file against the index; re-harvest only changed
or new files; drop entries whose files vanished; write the index back; return
all records sorted by `updated_at_ms` desc. `force: true` ignores the index.
Runs on `spawn_blocking`; never errors (missing roots → empty). The command is
registered in `build.rs` AppManifest + `capabilities/default.json`, and its
autogenerated permission TOML is committed — same drill as R2.

## 3. Conversations rail (UI)

The sidebar gains a two-mode header switch: **Terminals | Conversations**
(Terminals is today's view, unchanged). Conversations mode:

- Provider filter chips: All / Claude / Codex.
- Selecting a session opens a **detail pane** (below the list or as the rail's
  lower half): title, full cwd, provider, last-active time, summary and recap
  (whatever exists, regardless of the row display setting), the Resume button,
  an **Open transcript** button (§12 transcript mode — the complete
  conversation, any size), and the "Files touched" list (§11).
- Search box filtering on title + cwd + summary + recap (case-insensitive
  substring; same debounce feel as the folder searcher).
- Folder tree: user-created folders (create, rename, delete via header “+” and
  per-folder menu), then "Unfiled" holding everything unassigned. Right-click a
  session row → "Move to folder" / "Remove from folder". Deleting a folder
  unfiles its sessions (never touches provider files).
- Session row: provider badge, title, shortened cwd (leaf-preserving, like the
  folder palette), relative time, and secondary text per §6 display settings.
  Click selects; a Resume button on the selected row (and double-click)
  triggers §5. A footer line shows "N sessions · refreshed <ago>" with a
  manual refresh button (`force: true`).

State lives in a `ConversationsStore` (same `useSyncExternalStore` shape as
SettingsStore): records from `list_llm_sessions`, folders/assignments from
**`conversations_v1.json`** (allowlist +1):

```json
{ "version": 1,
  "folders": [{ "id": "uuid", "name": "..." }],
  "assignments": { "<provider>:<id>": "<folderId>" },
  "generated": { "<provider>:<id>": {
      "summary": "...", "recap": "...", "generatedAtMs": 0, "sourceMtimeMs": 0 } } }
```

## 4. Palette

`Ctrl+Shift+O` opens folders; **`Ctrl+Shift+R`** opens the session palette —
same overlay family as FolderSearch: fuzzy query over title/cwd/summary,
ArrowUp/Down, Enter = resume, Esc = close. Rows reuse the rail's row anatomy
minus folders. Shares ConversationsStore (no second scan).

## 5. Resume flow

On resume of record R:

1. Claude: if `R.cwd` is missing or the directory no longer exists → notice
   "The session's folder no longer exists (<path>)" and stop (Claude sessions
   are keyed to their project dir; resuming elsewhere cannot find them).
   Codex: threads are id-keyed globally, so a missing/vanished cwd degrades to
   opening the tab in the host default directory instead of refusing.
2. Create a tab via the existing create-with-cwd path (`createTabWithCwd`)
   with cwd = `R.cwd`, profile = settings default.
3. Wait for the shell's first OSC 9;9 report (the prompt-hook signal that the
   prompt is ready). Timeout 15 s → fall through and send anyway.
4. Write the resume command as terminal input, visibly:
   - claude: `claude --resume <id>\r`
   - codex: `codex resume <id>\r`
5. The tab title follows the normal terminal flow (no special casing).

If shell integration is OFF in settings, step 3 degrades to a fixed 1.5 s
delay. Command strings are built from the record id after validating it
matches `^[A-Za-z0-9-]+$` (ids are uuids; anything else is refused) — no
shell-metacharacter injection via a hostile index file.

## 6. Summaries and recaps

Two content kinds: **summary** (short one-liner) and **recap** (multi-line
"what was going on"). Claude Code does not persist its resume-recap to disk;
TermX's recap = the newest compaction block harvested from the transcript
(§1), else an LLM-generated recap when the engine allows.

**Engine setting** (`summaryEngine`): `disk-first` (default) | `disk-only` |
`llm`.

- disk-only: only harvested data; missing → nothing.
- disk-first: harvested data wins; the LLM fills only missing summaries/recaps.
- llm: the LLM (re)generates both kinds for every session as they go stale.

**LLM engine.** A UI-side scheduler + Tauri command
`generate_session_note(file_path, kind)` that shells out
`claude -p --model claude-haiku-4-5-20251001` with a bounded transcript
excerpt (last 8 KB) and a one-line/five-bullet prompt, 30 s timeout,
concurrency 1, min 10 minutes between generations per session, and only for
sessions currently visible in the rail/palette (lazy). Results cache in
`conversations_v1.json.generated` keyed with `sourceMtimeMs` — a session is
stale only when its file changed after the last generation. This is the
"every so often, lightweight" live-summary behavior: an active chat's file
keeps changing, so its note refreshes at most every 10 minutes.

**Content setting** (`summaryContent`): `summary` (A) | `recap` (B) |
`both` (A/B) | `none`.

**Display setting** (`summaryDisplay`): `hover` (tooltip on the row) |
`under-title` (secondary line(s), recap clamped to 3 lines). With content
`none`, rows show title + path only and the display setting is inert.

## 7. TERMX environment stamp

The host adds to every spawned profile's env (independent of shell
integration): `TERMX=1` and `TERMX_SESSION_ID=<host session id>`. The id is
known before spawn (registry assigns it first). Purpose: CLIs, CLAUDE.md
rules, and hooks can detect they are running inside TermX.

## 8. Settings additions

New "Conversations" section in the existing SettingsDialog, instant-apply:

- `conversationsRail`: bool (default true) — show the sidebar mode switch.
- `conversationsPalette`: bool (default true) — enable Ctrl+Shift+R.
- `summaryEngine`: radio, §6 (default `disk-first`).
- `summaryContent`: radio, §6 (default `summary`).
- `summaryDisplay`: radio, §6 (default `hover`).
- `sleepHiddenTerminals`: radio `off | 5 | 15 | 60` minutes (default `15`),
  §14.
- `onWindowClose`: radio `ask | keep-running | stop-all` (default `ask`),
  §15.

All seven join `TermxSettings` with tolerant per-field parsing like the
existing fields.

## 9. Error handling

- Adapters and `list_llm_sessions` never error: unreadable/malformed files are
  skipped; missing roots yield empty lists.
- Storage writes go through the existing atomic write_app_file path.
- LLM generation failures are silent in the UI (cache untouched; retried after
  the normal staleness window); the scheduler logs to console only.
- Resume-target validation failures produce the standard workspace notice.

## 10. Testing

- Rust: fixture-driven unit tests per adapter (temp dirs with synthetic
  jsonl heads/tails: summary lines, compaction blocks, malformed lines,
  slug-vs-cwd disagreement); index incrementality (unchanged files are not
  re-read — proven via a probe counter); command-level tests over temp roots.
- UI: ConversationsStore tests (filtering, folder ops, staleness math);
  component tests for rail rows/display modes and palette keyboard flow;
  resume-flow tests with a fake attachment asserting the exact input bytes
  written after a simulated OSC-ready signal, and the refusal path for a
  missing directory and a malformed id.
- Manual smoke (Michael): resume a real Claude and a real Codex session from
  the rail and the palette; flip all five settings live.

## 11. Session artifacts ("Files touched")

Claude transcripts record every `Write`/`Edit`/`MultiEdit`/`NotebookEdit`
tool call with its target path. Tauri command
`list_session_artifacts(file_path) -> Vec<Artifact>` streams the WHOLE
transcript line-by-line (bounded memory; a 100 MB file streams in well under a
second) and returns deduplicated
`{ path, kind: "created" | "edited", exists: bool }` — `kind` is `created` if
any Write targeted the path, else `edited`; `exists` is a stat at harvest
time. Runs on `spawn_blocking`, never errors (unreadable → empty). Harvested
**only when the detail pane's Files section is expanded**, then cached in
`conversations_v1.json` under
`artifacts: { "<provider>:<id>": { sourceMtimeMs, files: [...] } }` — re-run
only when the transcript's mtime moves. Codex transcripts don't record edits
comparably; artifacts are Claude-only in v1.

Detail-pane UI: file rows grouped created/edited, shown with the same
leaf-preserving truncation as the folder palette; vanished files grayed.
Click → open in the viewer (§12); right-click → "Open folder in new tab"
(create-with-cwd on the file's parent).

## 12. Native file viewer

A read-only viewer for looking at AI-produced files (specs, scripts, notes)
without leaving TermX. Markdown renders properly (headings, lists, tables,
fenced code); every other text file shows as clean monospace. One new Tauri
command `read_text_file(path) -> { content, truncated }`: 2 MB cap (truncated
flag set beyond), refuses binary (NUL-byte sniff in the first 8 KB), never
follows the request into an error dialog — failures surface as a one-line
notice in the viewer frame.

Surfaces and movement (Adobe-lite docking, §14):

- **Docked panel** (default): right side of the terminal area, drag-resizable;
  a dock-position control moves it right / bottom.
- **Overlay**: maximized reading mode. `Ctrl+Shift+M` toggles docked ↔
  overlay.
- **Tray**: minimizing collapses the viewer to a slim edge pill showing the
  file name — accessible, out of the way, never lost. Click restores.
- Entry points: artifacts list (§11), and terminal path links (the existing
  link detector gains a "view file" action alongside today's copy-path).
- Layout rule (F5 lesson, now a standing constraint): the viewer, pane
  toolbars, search bar, and tray must never overlap one another; docking
  reserves real space instead of floating over controls.

Viewer geometry (dock side, sizes, tray state) persists in
`ui_state_v1.json`.

**Transcript mode.** The viewer's second mode renders a session's COMPLETE
conversation from its transcript file — the terminal scrollback ring never
limits this, because the harness writes the full conversation to disk
independently of the terminal. Guarantees:

- Opens from the detail pane's "Open transcript" button, positioned at the
  END (most recent turns) — the "where were we" view — with a "Load earlier"
  control that pages backward.
- Backed by a windowed Tauri command
  `read_transcript_window(file_path, before_offset: Option<u64>, max_bytes: u32)
  -> { lines: Vec<String>, next_before_offset: Option<u64> }`: reads one
  bounded chunk ending at `before_offset` (default EOF), splits on newlines,
  discards the leading partial line and reports its offset as the next
  cursor. The full file is NEVER loaded; a 500 MB transcript costs the same
  per page as a 1 MB one.
- The UI parses each jsonl line tolerantly and renders user and assistant
  turns as formatted blocks (markdown for text), with tool calls/results
  collapsed to one-line stubs ("tool: Write ui/src/App.tsx") expandable in
  place. Unrenderable lines are skipped silently.
- Loaded chunks accumulate up to a memory guard (~10 MB parsed); loading
  beyond it drops the farthest-away chunks (re-loadable by scrolling back —
  offsets make this cheap).

**Transcript search.** `Ctrl+F` while the transcript has focus opens a
search bar with three modes — substring (default, case-insensitive),
regex, and fuzzy (subsequence) — plus next/prev navigation. Search runs
server-side so size never matters: Tauri command
`search_transcript(file_path, query, mode, filter, max_results) ->
Vec<{ offset: u64, snippet: String }>` streams the whole file in Rust
(`filter: all | user` restricts matches to user-turn lines), capped at
`max_results` (default 200) with a "more matches exist" flag. Selecting a
match loads the chunk at that offset and highlights it. Invalid regex shows
an inline error, never a crash.

**Jump to last user message.** A dedicated control (and `Ctrl+Shift+J`, the
same muscle memory as the terminal feature): first press jumps to the most
recent user turn, repeats walk to earlier user turns, scrolling to the
bottom resets the walk — implemented via `search_transcript` with
`filter: user`.

## 13. Terminal semi-sleep

After a terminal tab has been hidden (not the visible tab) for
`sleepHiddenTerminals` minutes, the UI disposes its xterm presentation — the
expensive DOM/renderer — while the host keeps the session running untouched.
Revealing the tab wakes it: reattach with replay, restoring scrollback and
the live process sub-second. The sidebar marks sleeping tabs with a subtle
"zZ" affordance; a sleeping tab's activity badge freezes until wake (accepted
trade).

**Resize discipline (the malformed-scrollback defense).** Replaying recorded
bytes into a terminal sized differently from when they were produced is what
garbles TUIs. Therefore, on EVERY reattach (wake, tab switch back, app
relaunch): the terminal is created at the session's recorded cols×rows, the
replay runs at those dims, and only then does fit-to-container resize the PTY
— so full-screen apps (Claude Code) receive one clean resize signal and
redraw themselves at the new width. Live resizes stay debounced through the
existing fit path. xterm's own reflow handles soft-wrapped lines. V2's smoke
explicitly includes: resize the window mid-Claude-Code-generation, scroll up,
verify no interleaved-width garbage beyond what the app itself repaints.

## 14. Performance principles and layout system

Standing principles for this batch and after:

- Nothing runs when unused: no scanning while the rail is closed; artifacts
  harvest on expand only; LLM notes only for visible rows, rate-limited;
  viewer loads one file; index is incremental; sleep reclaims renderers.
- Target: comfortable on older hardware with many sessions indexed and many
  tabs open (sleep bounds live renderers to roughly the visible set).
- **Adobe-lite docking (this batch)**: the new surfaces are movable within
  fixed slots — viewer docks right/bottom/overlay/tray, Conversations rail
  docks left/right, all panel edges drag-resize, all geometry persists in
  `ui_state_v1.json`. No overlapping controls, ever.
- **Action registry + editable trays (this batch, foundation)**: every
  toolbar/rail button is registered as an action chip
  `{ id, icon, label, run }` in one registry; each tray (sidebar footer, pane
  toolbar, viewer header) renders a persisted, ordered chip list from
  `ui_state_v1.json` rather than hardcoded buttons. Customization v1 is
  menu-driven and dependency-free: right-click a chip → "Remove from tray";
  a **Features dock** (opened from Settings or a rail button) lists every
  registered action with "Add to <tray>" per tray. Config is a few small
  string arrays — zero runtime cost; unknown ids in a stale config are
  ignored, and a "Reset layout" restores defaults.
- **Wave 2 (next batch, own design pass)**: true Adobe-grade manipulation on
  top of the registry — drag chips off trays, drag between trays, drag from
  the Features dock, floating tear-off trays, workspace presets. The registry
  above is deliberately shaped so Wave 2 changes interaction, not data.

## 15. Window close: safety and clarity

Closing the TermX window does NOT stop terminals — the host daemon keeps
every session (and any agent running in one) alive in the background. That
is the product's superpower (long-horizon tasks survive; measured daemon
idle cost: ~7 MB RAM, ~0 CPU) and also a safety hazard: someone watching an
agent misbehave may close the window expecting that to stop it. It must be
impossible to close TermX without understanding what happens.

- With `onWindowClose: ask` (the default), closing while any session is
  alive shows a dialog: **"Your terminals keep running in the background"**
  — body copy states that running programs and agents will continue and that
  reopening TermX restores them; buttons **Keep running** and
  **Stop everything** (sends the daemon Shutdown — the wire message already
  exists — killing all session process trees), plus a "Remember my choice"
  checkbox that writes `keep-running` or `stop-all` to settings.
- `keep-running` / `stop-all` close silently with that behavior; the setting
  can always be changed in the Settings pane, where the option text repeats
  the background-behavior explanation.
- No alive sessions → close is always silent.

## 16. Combine tabs side-by-side (merge / extract)

Two live sessions — often two agents' plans in one group — must be viewable
side by side even though they live in different tabs. Because sessions are
daemon-owned and panes are layout-tree positions, this is layout surgery
with zero session disruption (scrollback replays on remount):

- **Merge**: tab context menu (sidebar) gains "Side-by-side with active
  tab": the source tab's entire split subtree becomes a new right-hand
  sibling inside the active tab; the source tab disappears from the rail.
  Refused with a notice when the combined split depth would exceed the
  existing split-depth cap.
- **Extract** (the undo): every pane's toolbar gains "Pop out to own tab"
  (registered as a §14 action chip): the session leaves its split and
  becomes its own tab in the same group, restoring the pre-merge shape.
- Both are pure functions in `layoutOperations.ts` over `LayoutV1`,
  persisted through the normal layout-persistence path. Focus follows the
  merged-in pane. Sessions, attachments, and scrollback are untouched.
- Drag-and-drop merging (drag a tab onto a pane) belongs to Wave 2 with the
  rest of the drag system; v1 is menu-driven.
